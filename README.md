# Civitas

Civitas — Discord-бот для политико-экономической игры на одном сервере. Один участник Discord регистрирует одно гражданство. Бета проходит на игровом сервере с участниками. Интерфейс открывается на языке клиента Discord — русском или английском.

## Первые шаги

1. Попроси администратора добавить тебя в список допуска. Открой `/start` и нажми «Стать гражданином».
2. Нажми «Справочник команд» или введи `/help`. Выбери раздел и нажми на название команды, чтобы открыть её в Discord. Аргументы и подтверждение заполняются в интерфейсе команды.
3. Начни с «Кошелёк и переводы», чтобы посмотреть стартовый грант, или с «Найти работу», чтобы взять задание. Свои должности и имущество можно посмотреть в `/profile`.

## Запуск беты на игровом сервере

Запустите Docker Desktop. Из корня проекта в PowerShell создайте локальный файл настроек:

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
```

Укажите в `.env` токен Civitas в `CIVITAS_DISCORD_TOKEN` и ID игрового сервера в `CIVITAS_DISCORD_GUILD_ID`. Для установки используются области `bot` и `applications.commands`. При обновлении существующего развёртывания используйте прежний Compose-проект и том PostgreSQL, чтобы сохранить данные участников.

Чтобы включить синхронизацию роли, создайте обычную роль `Citizen`. Выдайте боту `Manage Roles` и расположите его роль выше `Citizen`. После запуска выберите роль через `/admin setup role`. Сверка повторяется раз в минуту. Бот выдаёт роль зарегистрированным участникам со статусом `VERIFIED` и снимает её с зарегистрированных участников с другими статусами. Изменение списка допуска само по себе не меняет статус гражданства.

Для учёта выходов включите `CIVITAS_TRACK_MEMBERSHIP=true` и `Server Members Intent` в Discord Developer Portal. После события выхода бот переводит запись в `LEFT` с аудитом. При подключении и каждые пять минут бот также проверяет состав, чтобы учесть пропущенные выходы. Если игрок успел уйти и вернуться во время простоя, бот увидит его текущее членство. После зафиксированного выхода гражданин заново вызывает `/citizen register`, сохраняя прежние ID и счета.

Compose передаёт боту `CIVITAS_COMPOSE_DATABASE_URL` из `.env` с адресом `db:5432`. При запуске `python -m civitas` на хосте задайте `CIVITAS_DATABASE_URL` с адресом `127.0.0.1:55432` для локальной БД из примера и передайте остальные настройки Discord в окружение процесса. `.env` хранится локально.

После запуска вызовите `/admin admission add` с аккаунта администратора Discord и выберите себя или другого участника. `/admin admission list` показывает сохранённый список приватно. `/admin admission remove` отзывает допуск и записывает основание. Для вышедшего участника можно указать ID из списка. Затем допущенные участники регистрируются через `/citizen register`.

При обновлении с прежней версии примените миграцию `0022_discord_admission` и первый раз запустите бота с прежним `CIVITAS_ALLOWED_USER_IDS`. Бот импортирует список при первом запуске для этой гильдии. После проверки `/admin admission list` строку можно убрать из `.env`. Новый сервер начинает с пустым списком, если строка не задана. Дальнейшие изменения через Discord видны сразу и сохраняются в PostgreSQL.

`/admin setup status` показывает сохранённые роли и канал отчётов. `/admin setup role` предлагает выбрать назначение и роль Discord. `/admin setup report_channel` принимает текстовый канал. Пустой аргумент роли или канала очищает настройку. При смене роли снимите прежнюю роль с участников через Discord, если она больше не нужна. После миграции `0023_guild_presentation` первый запуск бота импортирует прежние ID ролей и канала из окружения. После проверки `/admin setup status` эти строки можно удалить из `.env`.

Для первого сезона передайте утверждённый профиль после локального файла настроек. В дополнение к токену и ID сервера заполните в локальном `.env`:

| Переменная | Значение |
| --- | --- |
| `CIVITAS_NPC_REVIEWER_IDS` | ID пользователя, проверяющего NPC-задания |
| `CIVITAS_MARKET_ARBITER_IDS` | ID арбитра рынка |
| `CIVITAS_ASSET_ISSUER_IDS` | ID оператора государственного имущества |
| `CIVITAS_ELECTION_COMMISSIONER_IDS` | ID минимум двух разных членов комиссии через запятую |
| `CIVITAS_ELECTION_POLL_HOSTS` | Имя хоста ссылок на опросы, например `discord.com` для ссылок на сообщения Discord. Несколько хостов указываются через запятую. |

После запуска допустите назначенных игроков через `/admin admission add`. Команды казны проверяют действующие выборные мандаты с момента запуска. Остальная экономика доступна до выборов.

```powershell
docker compose --env-file .env --env-file config/season1.env run --build --rm --no-deps bot python -m civitas --check-config
docker compose --env-file .env --env-file config/season1.env run --build --rm bot alembic upgrade head
docker compose --env-file .env --env-file config/season1.env --profile bot up -d bot
```

Команда `--check-config` проверяет переменные запуска и завершается без сетевых подключений. В PowerShell можно запустить `python -m civitas --check-config` с теми же переменными, переданными через окружение процесса. Перед игровым запуском проверьте в `/admin admission list`, что оператор госимущества, проверяющий NPC, арбитр и хотя бы два члена комиссии допущены и прошли обычную регистрацию. Роли привязываются через `/admin setup role` на игровом сервере.


### Личный кошелёк

Для включения кошелька укажите оба целых неотрицательных значения `CIVITAS_STARTER_GRANT` и `CIVITAS_TREASURY_GENESIS`. В первом сезоне — `250` и `8000`. Если оба поля пустые, кошелёк отключён. Символ валюты задаёт `CIVITAS_CURRENCY_SYMBOL`, по умолчанию `₵`.

Примените миграции до запуска бота. Казна получает начальный выпуск один раз при первом запуске кошелька с положительной суммой. Новый подтверждённый гражданин получает грант в транзакции регистрации. Уже зарегистрированные граждане получают его при повторной регистрации или первом обращении к своему кошельку. Уже проведённый выпуск сохраняет исходную сумму при изменении конфигурации.

В приватной карточке `/wallet balance` кнопка «История операций» показывает последние десять операций. Историю можно открыть и через `/wallet history`. Для `/wallet transfer` выберите подтверждённого гражданина и сумму, затем подтвердите перевод в приватном сообщении. При сбое ответа проверьте историю и, пока доступна исходная кнопка, повторите подтверждение в том же сообщении. Повтор использует ключ исходной операции.

`/wallet receipts enabled:true` включает уведомления о новых проводках личного счёта, а `enabled:false` отключает их и отменяет ожидающие отправки. Уведомление приходит в личные сообщения Discord с номером и временем операции. Сумма и вид операции доступны в приватном ответе `/wallet receipt transaction_id`. Квитанцию можно открыть по номеру и при отключённых уведомлениях. Если Discord запрещает личную доставку, квитанция остаётся доступной в команде.

### NPC-задания

Включите кошелёк и заполните `CIVITAS_NPC_REVIEWER_IDS` списком Discord ID проверяющих. Проверяющие проходят обычный допуск и регистрацию и сверяют результат с опубликованным условием задания. Профиль сезона задаёт недельные пределы `CIVITAS_BUDGET_WEEKLY_LIMIT`, `CIVITAS_NPC_WEEKLY_LIMIT` и `CIVITAS_NPC_PERSONAL_WEEKLY_LIMIT` в `800`, `300` и `100` соответственно, награды `10–40`, начало недели в понедельник по UTC и нулевую паузу между взятиями заданий (`CIVITAS_NPC_COOLDOWN_MINUTES=0`).

Проверяющий публикует задание через `/jobs staff publish`. Гражданин открывает `/jobs list` с необязательным номером страницы, берёт задание через `/jobs claim` и сдаёт результат через `/jobs submit`. Проверяющие приватно просматривают очередь сдач через `/jobs staff review` с тем же параметром `page`. Одобрение перечисляет вознаграждение из казны в пределах доступных средств и недельных лимитов. Проверять собственную работу нельзя. Открытый бюджетный период сохраняет исходные границы и лимиты при перезапуске.

### Компании и рынок услуг

Профиль сезона задаёт одну активную фирму на основателя, сбор `CIVITAS_COMPANY_FEE=150` и налог `CIVITAS_SALES_TAX_BP=1000` (10%). Для рассмотрения споров задайте `CIVITAS_MARKET_ARBITER_IDS` со списком Discord ID допущенных и зарегистрированных граждан.

Подтвердите регистрацию фирмы через `/company register`. Сбор поступит в казну, а у фирмы появится отдельный счёт. Владелец выставляет услугу через `/market offer`. Покупатель открывает каталог `/market list`, листает страницы кнопками и выбирает услугу из меню. Открываются условия личного заказа с отдельной кнопкой оплаты. Для оплаты со счёта компании используйте `/market buy` с параметром `buyer_company_id`. Оплата хранится в эскроу до приёмки, отмены или решения арбитра. Цена и налоговая ставка фиксируются в заказе.

Команда `/market order` без номера заказа показывает список по страницам. Арбитр может открыть очередь независимых дел через `/market order disputes_only:true`. В команде с номером продавец отмечает сдачу, покупатель принимает результат или отменяет заказ до сдачи. Любая сторона может открыть спор. Независимый арбитр выбирает расчёт или полный возврат и указывает причину. Владелец фирмы может снять предложение через `/market withdraw`, указав причину. Витрина и новые покупки перестают использовать это предложение. Уже оплаченные заказы сохраняют цену и условия. Баланс фирмы можно посмотреть приватно в `/company info`.

### Разовые задания компаний

Команды `/work` доступны при включённом рынке. Владелец компании указывает сумму, условия и срок в `/work publish`. Подтверждение переводит оплату со счёта фирмы в эскроу. Если средств недостаточно, задание не публикуется. Гражданин выбирает задание в `/work list`, берёт его через `/work claim` и сдаёт результат в `/work submit` до указанного срока. `/work mine` показывает свои задания.

Владелец принимает результат через `/work accept`, после чего эскроу перечисляет всю сумму исполнителю. До сдачи работы `/work cancel` возвращает резерв компании. После сдачи сторона может открыть спор через `/work dispute`. Независимый арбитр из `CIVITAS_MARKET_ARBITER_IDS` решает спор в `/work resolve`. По истечении срока он также может отменить несданное задание или открыть спор по сданной работе без решения. Для разрешения спора нужен настроенный арбитр, который не является стороной задания. Доступ к сданным материалам ограничен сторонами и арбитрами при споре или просроченной приёмке.

### Первичная продажа имущества

Укажите Discord ID назначенного оператора в `CIVITAS_ASSET_ISSUER_IDS`. После регистрации он задаёт категорию, название, назначение, цену и основание выпуска через `/assets staff issue`. Общего лимита объектов в первом сезоне нет.

Гражданин просматривает `/assets catalog`, выбирает объект в `/assets buy` и подтверждает указанную цену. Оплатить можно с личного счёта или со счёта своей фирмы. Казна получает всю цену, а объект переходит покупателю той же транзакцией. `/assets mine` показывает личное имущество и имущество своих фирм. Каталог и список имущества поддерживают параметр `page`.

### Перепродажа личного имущества

Владелец создаёт предложение командой `/assets sell` с номером объекта, покупателем и ценой. Участники видят предложенные им сделки и свои предложения через `/assets resale`. Покупатель открывает `/assets resale_buy` с номером предложения, сверяет объект и суммы и подтверждает покупку. Продавец может снять открытое предложение через `/assets resale_cancel`. Для одного объекта одновременно действует одно предложение.

В профиле первого сезона `CIVITAS_ASSET_RESALE_TAX_BP=200`. Ставка фиксируется при создании предложения, налог округляется вниз до целой единицы. При подтверждении покупатель платит полную цену, продавцу поступает остаток после налога, казне начисляется налог и право переходит покупателю. Повторное подтверждение показывает прежнюю квитанцию. Ответы по сделке приватны. В отчёте казны видна только общая сумма налога.

### Бюджет и казённые контракты

Для ручного режима укажите `CIVITAS_TREASURY_INITIATOR_IDS` и `CIVITAS_TREASURY_APPROVER_IDS` со списками Discord ID зарегистрированных граждан. В первом сезоне госконтракты используют выборные полномочия и недельный лимит статьи `250` в пределах общего лимита `800`.

Уполномоченный проверяющий активирует статью недели через `/treasury approve_budget`. Инициатор оформляет заказ гражданину или компании через `/contracts create`. `/contracts list` показывает доступные пользователю заказы по страницам, от новых к старым. Независимый проверяющий резервирует оплату через `/contracts reserve`. Исполнитель сдаёт результат в `/contracts submit`, а проверяющий принимает работу и проводит платёж через `/contracts accept`. Отмена через `/contracts cancel` освобождает резерв. `/treasury budget` показывает текущие лимиты, расходы и резервы. Содержание сдачи доступно сторонам и уполномоченным сотрудникам приватно.

Резерв уменьшает доступный остаток казны и свободные лимиты статьи и недели. Приёмка переводит резерв в расход той недели, в которой его создали. Суммы по завершённым контрактам и история решений сохраняются.

### Публичный отчёт казны

`/treasury report` показывает сводку текущей бюджетной недели, а с `previous: true` — предыдущей завершённой недели. В отчёте есть начальный и конечный остатки казны, поступления и списания по видам, расходы и резервы статей, эмиссия, открытые эскроу и счётчики операций. В личные счета и данные исполнителей отчёт не заглядывает. Платёж по контракту отражается в движении денег на дату оплаты, а в расходах статьи относится к неделе резервирования.

Для автоматических двуязычных публикаций выберите текстовый канал через `/admin setup report_channel`. Боту нужны права просмотра канала, отправки сообщений и `Embed Links`. Интервалы используют `CIVITAS_BUDGET_TIMEZONE`. При первом включении бот ставит в очередь предыдущую завершённую неделю, затем догоняет пропущенные недели. Запись очереди хранит исходный канал и агрегаты. Замена или очистка канала влияет на новые публикации. Повторы уже поставленных в очередь публикаций используют прежний канал.

### Голосование на игровом сервере

Игрок голосует в EasyPoll. Комиссия открывает выборы в Civitas и сверяет сохранённый список избирателей. Для опроса назначьте роль допуска участникам из этого списка. В EasyPoll укажите эту роль в `allowedrole`, один выбор в `maxchoices`, отдельный вариант «Воздерживаюсь» и время окончания из Civitas. Для президентских и сенатских выборов создаются отдельные опросы. После закрытия комиссия переносит итог в Civitas и сохраняет ссылку на сообщение с опросом.

### Выборы и мандаты

Укажите `CIVITAS_ELECTION_COMMISSIONER_IDS` со списком как минимум двух разных членов комиссии и `CIVITAS_ELECTION_POLL_HOSTS` с разрешёнными хостами ссылок на результаты. Члены комиссии должны быть допущенными гражданами. Профиль сезона задаёт порог в 10 граждан, кворум 40% с минимумом 4, три места в парламенте, срок мандата 28 дней, голосование 48 часов и продление на 24 часа.

Комиссия открывает выборы через `/election commission open`. При открытии бот фиксирует граждан со статусом `VERIFIED` и действующим допуском в PostgreSQL. Кандидатам нужен тот же допуск. Уже открытые голосования используют сохранённый снимок. Комиссия сверяет его приватно через `/election commission voters`. После закрытия голосования один член комиссии вводит ссылку, число участников и агрегированные голоса по кандидатам через `/election commission record`. Другой член комиссии подтверждает результат через `/election commission certify`. Для записи и подтверждения нужны два члена комиссии, которые не баллотируются в этом голосовании. Индивидуальные бюллетени остаются у сервиса голосования. `/government offices` показывает действующие мандаты, `/election results` — опубликованные результаты.

Для импичмента действующего президента комиссия фиксирует список избирателей через `/election commission open_impeachment` и сверяет допуск через `impeachment_voters` в той же группе команд. После закрытия публичного опроса один член комиссии записывает ссылку, число участников и число голосов за отстранение через `record_impeachment`. Второй подтверждает через `confirm_impeachment`. Президент не может поставить ни одну подпись. При выполненном кворуме и двух третях голосов за вторая подпись сразу прекращает полномочия в БД. Discord-роль снимается при следующей сверке. `/government impeachment` показывает публичные агрегаты и итог по номеру.

Комиссия продолжает уже открытые выборы или сохраняет подтверждённого преемника и его дату вступления. При их отсутствии она открывает внеочередные выборы через `/election commission open` на полный срок. Действующие мандаты депутатов сохраняются.

Выберите отдельные игровые роли `President` и `Senator` через `/admin setup role`. Выдайте боту `Manage Roles` и разместите его роль выше обеих. Если роль уже назначалась как `Member of Parliament`, её можно переименовать в Discord с сохранением привязки. Сверка охватывает пользователей с мандатами в БД. В профиле первого сезона действующий президент оформляет казённый контракт, а независимый действующий сенатор утверждает бюджет, резервирует средства и принимает работу. Проверка идёт по сроку мандата в БД.

При включённых выборах президент выдвигает верховного судью через `/court nominate`. Двое действующих сенаторов подтверждают одно назначение через `/court approve`. `/court current` показывает действующий мандат, `/court nomination` показывает подписи по номеру выдвижения. Вторая подпись открывает самостоятельный срок на 28 дней. [Процедуры суда первого сезона](docs/12_COURT.md)

Сенаторы вносят уже принятый и опубликованный в RP закон через `/law register`. Укажите постоянный код, текст, ссылку на сообщение и дату вступления в силу с часовым поясом, например `2026-11-16T12:00:00+03:00`. Другой действующий сенатор читает редакцию через `/law revision` и утверждает её через `/law confirm`. `/law show` показывает редакцию на текущую или указанную дату. `/law list` показывает действующие законы.

Президент вносит опубликованный указ через `/decree register`. Сенатор сверяет текст со ссылкой через `/decree revision`, затем подтверждает через `/decree confirm`. `/decree show` ищет указ по коду и дате, `/decree list` показывает действующие указы.

Президент выдвигает прокурора через `/prosecutor nominate` или предлагает его освободить через `/prosecutor propose_removal`. Двое действующих сенаторов утверждают предложение через `/prosecutor approve`. `/prosecutor current` показывает действующего прокурора, `/prosecutor motion` — подписи по номеру предложения.

В реестр суда подают гражданские иски через `/court case civil`, государственные обвинения через `/court case charge`, жалобы на законы через `/court case challenge` и жалобы на указы через `/court case challenge_decree`. Судья назначает и переносит заседание через `/court case schedule`. `/court case list` показывает сводки, а `/court case show` добавляет текст подачи в приватный ответ уполномоченному участнику.

Судья выносит решение по административной жалобе через `/court case decide_challenge`. `/court case decision` показывает решение и его мотивировку. Если жалоба удовлетворена, редакция сразу приостанавливается и появляется в `/court case returns` для принявшего органа. Поиск действующей редакции возвращает предшествующую редакцию, если она доступна.

`/election commission active` показывает комиссии номера и сроки незавершённых голосований. После первого подтверждённого срыва комиссия указывает номер исходных выборов в `retry_of_id` при открытии повторного голосования. Если второй итог тоже подтверждает срыв, `/election results` показывает игровой политический кризис. Когда участники разыграли кризис вручную, один член комиссии предлагает открыть новый цикл через `/election commission resolve_crisis`, второй независимо подтверждает через `/election commission confirm_crisis`. `/help` показывает доступные в гильдии группы команд. `/profile` приватно показывает гражданский статус, действующие должности и до пяти компаний и объектов имущества.

Если опрос потерян или его итог нельзя проверить, один член комиссии предлагает отмену через `/election commission cancel`, второй подтверждает через `/election commission confirm_cancel`. Указывайте в предложении причину, которую можно показать всем гражданам. При открытии замены укажите номер отменённых выборов в `replacement_of_id`. После ничьей при повторе и его замене укажите оставшихся допущенных кандидатов. Если их меньше, чем мест, повторите выдвижение в той же попытке.

Проверяйте права всех игровых ролей на сервере, в категориях и в каналах. Бот пропускает синхронизацию, если роль предоставляет права администрирования или модерации либо у самого бота включён `Administrator`. Если права ранее выданной роли изменили вручную, исправьте их в настройках Discord.

### Техническое обслуживание

Задайте `CIVITAS_TECHNICAL_OPERATOR_IDS` со списком Discord ID технических операторов. `/admin audit [page]` показывает приватную сводку критических действий. `/admin maintenance` показывает текущее состояние. С аргументами `enabled` и `reason` команда включает или выключает паузу. Пока она действует, доступны история и отчёты, а PostgreSQL отклоняет новые проводки и резервы казны.
