**Язык проекта:** русский\
**Статус:** гражданство, синхронизация роли, личный кошелёк, NPC-задания, компании, рынок услуг, первичная продажа имущества, недельный бюджет, казённые контракты и публичный отчёт казны. Политический цикл входит в следующие срезы.

## Быстрый старт для Codex

1. Распаковать папку в корень нового Git-репозитория.
2. Прочитать этот `README.md` и `AGENTS.md`, затем документы `docs/` в указанном ниже порядке.
3. До реализации прочитать `docs/09_DECISIONS_AND_QUESTIONS.md`: там отделены принятые требования от предлагаемых параметров.
4. Начать с планирования **этапа 1**, а не со всего проекта сразу. Шаблон первого запроса — `prompts/START_CODEX.md`.
5. Не создавать систему персонажей: аккаунт пользователя Discord сам является гражданином.

## Суть проекта

**Civitas** — многопользовательская политико-экономическая игра в рамках **одного Discord-сервера** (до ~30 участников). Участники — граждане виртуальной республики. Они работают в государственных, частных и NPC-организациях, открывают компании, торгуют, владеют недвижимостью и активами, избирают власть, принимают законы и влияют на бюджет. Глубина экономики сочетается с доступным социальным RP.

**Основной интерфейс — Discord:** slash-команды, кнопки, select-menu, модальные формы, каналы, форумные темы, роли. Отдельный сайт, приложение и RPG-персонажи не входят в первую версию.

## Статус решений

- **Подтверждено пользователем:** ориентир — около 30 человек, без жёсткого лимита; баланс симуляции и развлечения; глубокая экономика; Discord-only на старте; пользователь Discord = гражданин, **без** отдельного персонажа, здоровья, возраста, навыков или старения; разработка и тестирование в Codex.
- **Направления, согласованные для проектирования:** президент, парламент, партии/выборы, работа, NPC-работодатели, бизнес игроков, налоги, бюджет, имущество и недвижимость.
- **Рабочие предложения, требующие утверждения:** устройство власти, сроки выборов, цены, налоговые ставки, стартовые балансы, лимиты, конкретные обязанности должностных лиц и состав MVP. Все такие значения вынесены в конфигурацию и реестр решений.

## Базовые принципы

1. **Люди создают игру:** автоматизация сокращает рутину, а не заменяет взаимодействие граждан.
2. **Экономика замкнута и учёт проверяем:** никакого безлимитного `/work`, все движения денег записываются и сверяются.
3. **Маленькое население:** работа доступна через NPC, если реальные работодатели неактивны; минимум обязательных государственных должностей.
4. **Один Discord-аккаунт — один гражданин в данном сервере**, при дополнительной защите выборов от мультиаккаунтов. Полной гарантии личности Discord не даёт.
5. **Политические роли — игровые:** они не получают права владельца/администратора Discord.
6. **Без реальных денег:** внутриигровая валюта не обменивается на реальные деньги, не является финансовым активом.
7. **Сначала вертикальный сценарий:** зарегистрироваться → заработать → открыть компанию → продать услугу → уплатить налог → потратить бюджет.
8. **Не добавлять систему персонажей и расширения вне MVP без явного запроса.**

## Терминология

- **Игрок / гражданин:** Discord-пользователь с зарегистрированным гражданством в этом сервере.
- **Республика:** игровая политическая система, не отдельная юридическая юрисдикция.
- **Казна:** игровой государственный денежный счёт.
- **NPC:** контролируемая ботом организация, а не отдельный человек-персонаж.
- **Civitas:** собственный бот и его серверное приложение.
- **MVP:** минимальный завершённый набор для запуска игрового цикла.
- **Предлагаемый параметр:** настраиваемое число или правило, которое ещё не утверждено пользователем.

## Локальный запуск первого среза

Бот отвечает на `/start`, `/citizen register` и `/profile` в одной настроенной гильдии. Описания команд и ответы доступны на русском и английском. Бот использует русский при русской локали клиента Discord, для остальных локалей — английский. Для разработки используется список заранее допущенных Discord ID. Пустой список закрывает доступ всем. База хранит статус гражданства и аудит регистрации.

Выполните команды из корня проекта в PowerShell.

```powershell
Copy-Item .env.example .env
docker compose up -d --wait db
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[test]'
$env:CIVITAS_DATABASE_URL = 'postgresql+psycopg://civitas:civitas-local@127.0.0.1:55432/civitas'
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m pytest
$env:CIVITAS_TEST_DATABASE_URL = $env:CIVITAS_DATABASE_URL
.\.venv\Scripts\python.exe -m pytest
```

Первый прогон пропускает интеграционные тесты, если `CIVITAS_TEST_DATABASE_URL` не задан. Второй использует отдельную временную схему PostgreSQL на каждый тест. Для него нужна локальная тестовая БД с правом создания схем. Токен Discord тестам не нужен.

Для ручной проверки на закрытом сервере задайте в локальном `.env` токен тестового бота (`CIVITAS_DISCORD_TOKEN`), ID сервера (`CIVITAS_DISCORD_GUILD_ID`) и ID допущенных пользователей через запятую (`CIVITAS_ALLOWED_USER_IDS`). Пригласите приложение на этот сервер со scope `bot` и `applications.commands`. Для текущих команд достаточно установки без `Administrator` и без привилегированных intents.

Чтобы включить синхронизацию роли, создайте обычную роль, например `Citizen`, и укажите её Discord ID в `CIVITAS_CITIZEN_ROLE_ID`. Выдайте боту `Manage Roles` и расположите его роль выше `Citizen`. Сверка начинается после подключения бота и повторяется раз в минуту. Бот выдаёт роль зарегистрированным участникам со статусом `VERIFIED` и снимает её с зарегистрированных участников с другими статусами. Изменение списка допуска само по себе не меняет статус гражданства. Если поле с ID роли пустое, работают только команды.

Примените миграции и запустите бота.

```powershell
docker compose run --build --rm bot alembic upgrade head
docker compose --profile bot up -d bot
```

Compose передаёт боту `CIVITAS_COMPOSE_DATABASE_URL` из `.env` с адресом `db:5432`. При запуске `python -m civitas` на хосте задайте `CIVITAS_DATABASE_URL` с адресом `127.0.0.1:55432` для локальной БД из примера и передайте остальные настройки Discord в окружение процесса. `.env` хранится локально.

Для ручной проверки переключите язык клиента Discord между русским и английским, выполните `/start`, `/citizen register` и `/profile`. Проверьте язык описаний и ответов, неизменность статуса при повторной регистрации и появление настроенной роли после сверки.

### Личный кошелёк

Для тестового запуска укажите оба целых неотрицательных значения `CIVITAS_STARTER_GRANT` и `CIVITAS_TREASURY_GENESIS`. Пример для закрытого теста — `250` и `8000`. Если оба поля пустые, кошелёк отключён. Символ валюты задаёт `CIVITAS_CURRENCY_SYMBOL`, по умолчанию `₵`.

Примените миграции до запуска бота. Казна получает начальный выпуск один раз при первом запуске кошелька с положительной суммой. Новый подтверждённый гражданин получает грант в транзакции регистрации. Уже зарегистрированные граждане получают его при повторной регистрации или первом обращении к своему кошельку. Уже проведённый выпуск сохраняет исходную сумму при изменении конфигурации.

Команды `/wallet balance` и `/wallet history` показывают личный баланс и последние десять операций приватно. Для `/wallet transfer` выберите подтверждённого гражданина и сумму, затем подтвердите перевод в приватном сообщении. При сбое ответа проверьте историю и, пока доступна исходная кнопка, повторите подтверждение в том же сообщении. Повтор использует ключ исходной операции.

### NPC-задания

Включите кошелёк и заполните `CIVITAS_NPC_REVIEWER_IDS` списком Discord ID проверяющих. Проверяющие проходят обычный допуск и регистрацию. Укажите недельные пределы `CIVITAS_BUDGET_WEEKLY_LIMIT`, `CIVITAS_NPC_WEEKLY_LIMIT`, `CIVITAS_NPC_PERSONAL_WEEKLY_LIMIT` и диапазон `CIVITAS_NPC_REWARD_MIN` / `CIVITAS_NPC_REWARD_MAX`. Для теста можно взять предложенные `800`, `300`, `100` и `10–40`. По умолчанию неделя начинается в понедельник по UTC. Часовой пояс задаётся `CIVITAS_BUDGET_TIMEZONE`, пауза между взятиями заданий — `CIVITAS_NPC_COOLDOWN_MINUTES`.

Проверяющий публикует задание через `/jobs staff publish`. Гражданин открывает `/jobs list`, берёт задание через `/jobs claim` и сдаёт результат через `/jobs submit`. Проверяющие видят сдачи приватно и принимают или отклоняют их в `/jobs staff`. Одобрение перечисляет вознаграждение из казны в пределах доступных средств и недельных лимитов. Проверять собственную работу нельзя. Открытый бюджетный период сохраняет исходные границы и лимиты при перезапуске.

### Компании и рынок услуг

Включите кошелёк и задайте `CIVITAS_COMPANY_FEE`, `CIVITAS_COMPANY_LIMIT` и `CIVITAS_SALES_TAX_BP`. Предложенные значения для закрытого теста — `150`, `1` и `1000`. Налог указывается в базисных пунктах: `1000` означает 10%. Для рассмотрения споров задайте `CIVITAS_MARKET_ARBITER_IDS` со списком Discord ID допущенных и зарегистрированных граждан.

Подтвердите регистрацию фирмы через `/company register`. Сбор поступит в казну, а у фирмы появится отдельный счёт. Владелец выставляет услугу через `/market offer`. Покупатель открывает каталог `/market list`, затем проверяет условия и подтверждает `/market buy`. Он может оплатить заказ со своего счёта или со счёта своей фирмы. Оплата хранится в эскроу до приёмки, отмены или решения арбитра. Цена и налоговая ставка фиксируются в заказе.

В `/market order` продавец отмечает сдачу, покупатель принимает результат или отменяет заказ до сдачи. Любая сторона может открыть спор. Арбитр, который не участвует в сделке, выбирает расчёт или полный возврат и указывает причину. Баланс фирмы можно посмотреть приватно в `/company info`.

### Первичная продажа имущества

Укажите `CIVITAS_ASSET_ISSUER_IDS` со списком Discord ID зарегистрированных граждан, которым разрешено выставлять государственное имущество. Для теста такой сотрудник задаёт категорию, название, назначение, цену и основание выпуска через `/assets staff issue`.

Гражданин просматривает `/assets catalog`, выбирает объект в `/assets buy` и подтверждает указанную цену. Оплатить можно с личного счёта или со счёта своей фирмы. Казна получает всю цену, а объект переходит покупателю той же транзакцией. `/assets mine` показывает личное имущество и имущество своих фирм. Каталог и список имущества поддерживают параметр `page`.

### Бюджет и казённые контракты

Для тестового запуска укажите `CIVITAS_TREASURY_INITIATOR_IDS` и `CIVITAS_TREASURY_APPROVER_IDS` со списками Discord ID зарегистрированных граждан. Контракты используют общий недельный лимит `CIVITAS_BUDGET_WEEKLY_LIMIT`, часовой пояс `CIVITAS_BUDGET_TIMEZONE` и отдельный лимит `CIVITAS_CONTRACT_WEEKLY_LIMIT`. Предложенный лимит статьи для теста — `250` при общем лимите `800`.

Уполномоченный проверяющий активирует статью недели через `/treasury approve_budget`. Инициатор оформляет заказ гражданину или компании через `/contracts create`. Независимый проверяющий резервирует оплату через `/contracts reserve`. Исполнитель сдаёт результат в `/contracts submit`, а проверяющий принимает работу и проводит платёж через `/contracts accept`. Отмена через `/contracts cancel` освобождает резерв. `/treasury budget` показывает текущие лимиты, расходы и резервы. Содержание сдачи доступно сторонам и уполномоченным сотрудникам приватно.

Резерв уменьшает доступный остаток казны и свободные лимиты статьи и недели. Приёмка переводит резерв в расход той недели, в которой его создали. Суммы по завершённым контрактам и история решений сохраняются.

### Публичный отчёт казны

`/treasury report` показывает сводку текущей бюджетной недели, а с `previous: true` — предыдущей завершённой недели. В отчёте есть начальный и конечный остатки казны, поступления и списания по видам, расходы и резервы статей, эмиссия, открытые эскроу и счётчики операций. В личные счета и данные исполнителей отчёт не заглядывает. Платёж по контракту отражается в движении денег на дату оплаты, а в расходах статьи относится к неделе резервирования.

Для автоматических двуязычных публикаций укажите `CIVITAS_TREASURY_REPORT_CHANNEL_ID` с ID текстового канала этой гильдии. Боту нужны права просмотра канала, отправки сообщений и `Embed Links`. Интервалы используют `CIVITAS_BUDGET_TIMEZONE`. При первом включении бот ставит в очередь предыдущую завершённую неделю, затем догоняет пропущенные недели. Запись очереди хранит исходный канал и агрегаты, а при ошибке Discord остаётся доступной для повтора после перезапуска.
